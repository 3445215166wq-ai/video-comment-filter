### 5.3 修复：中文路径下分词器加载失败

- **现象**：`Not found: "...\sentencepiece.bpe.model": No such file or directory`，而文件就在那里。
- **根因**：`SentencePieceProcessor::Load()` 接收**窄字符路径**，Windows 下按 ANSI 码页
  （GBK/936）解析。路径含中文就必然失败。原代码能跑，纯粹因为当年的目录是纯英文。
- **修法**：用宽字符 API 读取原始字节，再 `LoadFromSerializedProto()`。

### 5.5 修正：模型身份判断（我判断错了一次）

- **错误推断**：看到 `model.onnx` 有 448 MB，与英文 MiniLM-L6（约 90 MB）差距过大，
  就断定"这不是 MiniLM"。
- **实测结果**：117,505,920 参数（117.5M）/ 隐藏维 **384** / **12 层** / 词表 250,037
  → 是 **多语言 MiniLM-L12-H384**。
- **为什么体积大**：`250037 × 384` 的嵌入矩阵单独就占 96M 参数（约 384 MB），与层数无关。
- **教训**：不能用文件大小判断模型家族，要测维度、词表、参数量。

### 5.6 根治：分词表 ID 与模型 embedding 行号错位（本项目最严重的缺陷）

- **现象**：程序不报错、不崩溃、照常有输出，但语义筛选失效——相关句对与无关句对的
  平均余弦几乎相等，方向还略微相反（区分度 **−0.0149**）。
- **根因（2026-11-19 晚，两次更正后的最终结论）**：这是 **XLM-R 的既有设计**——
  `spm` 的原始 id 与 fairseq 词表（模型实际使用的 token id）**相差 1 位**。
  证据：本项目所用的 `sentencepiece.bpe.model`（SHA256 `CFC8146A…`）与 **`xlm-roberta-base`
  官方发布的 spm 字节完全相同**；HuggingFace 在 `tokenization_xlm_roberta.py` 中用
  `self.fairseq_offset = 1` 显式补偿（源码注释里就有那张对照表，`<mask>` 的位置
  `len(sp_model)+1 = 250001` 也与之吻合）。
  **本项目的错误是：直接用 SentencePiece C++ 库取原始 id，却没有实现这个 offset。**
  走 HF `AutoTokenizer` 不会出问题，绕过它就会整体错位。
  （此前两个错误结论——"被第三方转换工具搞坏"和"上游仓库自相矛盾"——均已推翻。）
- **一个反直觉的比例**：出错的是 4 个特殊词元（占词表 0.002%），被破坏的是 99.998%。
- **修法（方案一，最终采用）**：**分词表保持上游原版、一字节不改**，在
  `VideoFilteringCore/model/text_preproc.cpp` 顶部实现 `SpmIdToModelId()`，
  复刻 HF `XLMRobertaTokenizer` 的 `fairseq_offset = 1`；特殊词元直接用模型 id 常量
  （`<s>=0/<pad>=1/</s>=2`），不再向 spm 查询。
  选它而非"重建 spm 把偏移固化进文件"的理由：**不要 fork 上游产物**——
  改了 spm 就产出一份只有本项目理解的私有文件，别人配 HF 用会偏移两次，上游更新时还会漂移。
  **数据保持标准、适配放在边界。**
- **验证**：同一批 9 句语料，代码侧补偿后语义区分度 **+0.2894**（与文件侧固化方案数值完全一致）；
  端到端程序启动正常、工作集约 559 MB。
- **验证（两级，缺一不可）**：
  1. `tools/spm_probe.cpp` 用项目实际链接的 `sentencepiece.lib` 对比新旧文件 →
     9 句 piece 字符串序列**逐字一致**，id 映射违规 **0 条**
  2. 语义区分度 **−0.0149 → +0.2894**
- 完整复盘见 [`TOKENIZER_ALIGNMENT.md`](TOKENIZER_ALIGNMENT.md)。

## 5.10 补测试、修决策矩阵缺陷、实测真实区分度（2026-11-21）

### 5.10.1 发现并修复一个潜伏三个月的逻辑缺陷

`SimilarityPolicy::Evaluate()` 里「负向命中」这个事件，在两处代码路径上返回了**相反的值**：

| 模式 | 代码 | 命中后的动作 |
|---|---|---|
| 仅负向 | `neg_hit ? 1 : 0` | 1 = 滚动跳过 ✓ 正确 |
| 双向 | 直接 `filter_result = 0` | 0 = **停在负面视频上** ✗ 错误 |

两段**单独看都自洽**（各自的注释写的也是对的），并排成 8 行真值表才暴露矛盾。
**为什么能藏三个月**：负向阈值偏高，加上 2026-11-19 之前语义区分度失效（见 5.6），
这个分支几乎从不执行——它是被另一个缺陷"保护"着活下来的。

**修法**：不取最小补丁，而是把「负向命中就滚走」合并为**唯一一处表达**：

```cpp
// 规则一：负向命中 → 一律滚动到下一条，与模式无关
if (negative_enabled && neg_hit) { decision.filter_result = 1; return decision; }
// 规则二：仅启用负向且未命中 → 停在该视频
if (negative_enabled && !positive_enabled) { decision.filter_result = 0; return decision; }
```

短路行为不变（负向命中仍先返回，双向模式下省一次正向计算）。
`ARCHITECTURE.md` 的决策矩阵同步订正——原表把「仅负向命中」也记成 `0 停止`，与代码本就不一致。

### 5.10.3 实测真实数据上的语义区分度

用**两组真实抖音评论**（耳机购物 / 高数考试，各 8 条，主题经人工确认），
计算组内与跨组的平均余弦：

| 指标 | 值 |
|---|---|
| A 组内（耳机）平均余弦 | 0.6093 |
| B 组内（高数）平均余弦 | 0.7811 |
| 同主题平均 | 0.6952 |
| 跨主题平均 | 0.6303 |
| **区分度（同 − 跨）** | **+0.0649** |

> **结论：真实短评论上的区分度 +0.0649，远低于 5.6 节的 +0.2894。**

> 不是调好了，是模型能力边界就在这。

### 5.10.4 一个方法论副产品：「同一视频」≠「同一语义主题」

实测 A 组内（0.6093）反而**低于**跨主题（0.6303）。原因不是编码器坏了，而是耳机那组
评论话题是散的：`还是SBC`（技术）、`他要是99我就买了`（价格）、`这不是挤奶器吗`（玩笑）、
`打FPS游戏好用吗`（使用场景）——它们只共享"同一个视频"，不共享语义主题。
而高数那组都带"考试/挂科"强情绪，组内高达 0.7811。

**启示**：按视频取均值做模板会稀释语义；若要提升筛选效果，聚合单位应该按语义而非按视频。

## 5.11 语义主题分类可行性实测（2026-11-21）

### 5.11.1 为什么要测这个

一个自然的想法是：既然能算相似度，那就能把评论**按主题分类**（敌意对立 / 政策抱怨 / 价格咨询……）。
但在 5.10.3 里真实评论上的整体区分度只有 **+0.0649**，这个数字有两种截然不同的解读，
而工程结论完全相反：

- 若**所有主题都糊在一起** → 加分类器没用，必须换更强的编码器
- 若**只有部分主题糊** → 零样本分类（把模板从 2 组扩到 N 组）就够用

不测就是赌。工具：`tools/topic_matrix.cpp`，语料 `tools/topic_corpus3.txt`。

### 5.11.2 数据与结果

30 条**真实评论**，5 类，来源可追溯（B 站公开评论接口 / 抖音网页复制）：

| 类别 | 条数 | 来源 | 组内 | 对外 | 差 | 判定 |
|---|---|---|---|---|---|---|
| 敌意对立 | 7 | B 站 | 0.7066 | 0.6624 | **+0.0442** | 可分 |
| 制度抱怨 | 6 | B 站 | 0.7080 | 0.6827 | **+0.0253** | 可分 |
| 中性讨论 | 5 | B 站 | 0.5991 | 0.6375 | **−0.0384** | **不可分** |
| 考试焦虑 | 7 | 抖音 | 0.8180 | 0.6966 | **+0.1214** | 可分 |
| 求购价格 | 5 | 抖音 | 0.7507 | 0.6803 | **+0.0704** | 可分 |

整体：组内 0.7165 / 对外 0.6719 / **区分度 +0.0446**。

三种零样本决策规则的留一法准确率（随机基线 20%）：

| 决策规则 | 准确率 | 逐类 |
|---|---|---|
| 最近质心（原始） | 17 / 30 = **56.7%** | 焦虑 7/7、敌意 5/7、价格 3/5、制度 2/6、中性 0/5 |
| **最近质心 + 列标准化** | 19 / 30 = **63.3%** | 焦虑 6/7、敌意 5/7、价格 3/5、制度 3/6、中性 2/5 |
| kNN（k=2） | 15 / 30 = 50.0% | 焦虑 7/7、敌意 4/7、价格 3/5、制度 1/6、中性 0/5 |

### 5.11.3 三个结论

**① 决策规则能救约 6.6 个百分点，但上限被模型锁死。**
列标准化（按类去掉得分偏移与量纲）把 56.7% 提到 63.3%；kNN 反而更差。
这说明"最近质心偏置"是真实存在的（类内越紧致，越容易变成吸铁石），但调规则并不能突破模型能力。

**② 「中性讨论」在所有方法下都失败，而这不是算法问题。**
它的组内相似度（0.5991）**比它对外的还低**，任何决策规则都赢不了。根因是：
**「中性」不是一个语义类别，而是一个"情绪强度"标签。**
`paraphrase-multilingual-MiniLM` 编码的是**语义内容**，不是情绪强度——
"社会保险是核心部分"和"请问能讲一下市场经济"内容上毫无关系，只是都不激烈，
所以它们不会彼此相似。

→ 这是**类目设计错误**，不是模型不行。要判"中性"，只能用**排除法**
（判它不像已知的 N 个类 → 归为中性/其他），不能用分类法直接建"中性"类。

**③ 敌意对立的召回只有 71%（5/7），用于屏蔽还不够。**
漏判约 29%。要继续提升只有两条路：换更强编码器（代价见 5.10 的模型规格），
或者把"敌意"再拆细、每类补到 ≥8 条真实样本重测。

### 5.11.4 一次失败尝试（保留作反例）

在发现最近质心偏置后，第一反应是"把该类天生的组内相似度扣掉"：

```cpp
score = 平均相似度(样本, 类成员) - 类内平均相似度;
```

结果准确率从 56.7% **掉到 26.7%**。原因：中性讨论的组内均值最低（0.5991），
减掉它等于给它加成，**吸铁石从"考试焦虑"换成了"中性讨论"**——偏差没有消失，只是换了一头。

教训：**归一化必须去掉"类级别的偏移与量纲"，而不是减去某个类自己的基准值。**
前者用列标准化（z-score）才对。

### 5.11.5 落地建议

- **类目必须有"抓手"**：每个类要能说出「具体对象 + 明确态度」，例如
  `人身攻击`（对象=人，态度=敌意）、`政策不满`（对象=政策，态度=不满）。
  **不要留「中性 / 正常 / 其他」这类兜底大类**——它们在语义空间里没有凝聚性。
- **不要指望用这套模型做细粒度主题分类**；能做的是"态度鲜明"维度的粗分类。
- 若真要提升，优先换编码器而不是继续调规则；换之前先用本工具量出当前基线。

### 5.11.6 按"具体话题 × 明确态度"重做类目：**实测无效**（负结果）

按 5.11.5 的建议，把「中性讨论」整类删掉，剩下四类都写成「具体对象 + 明确态度」：

| 类别 | 对象 | 态度 | 组内 | 对外 | 差 | 判定 |
|---|---|---|---|---|---|---|
| 性别对立攻击（6 条） | 异性群体 | 敌意 | 0.7209 | 0.6900 | **+0.0309** | 勉强 |
| 养老金政策不满（6 条） | 养老社保政策 | 不满 | 0.7080 | 0.7014 | **+0.0066** | **等于不可分** |
| 考试焦虑（7 条） | 考试 | 焦虑 | 0.8180 | 0.7175 | **+0.1005** | 可分 |
| 商品比价求购（5 条） | 商品价格 | 想买 | 0.7507 | 0.7033 | **+0.0473** | 弱可分 |

分类准确率（随机基线 25%）：最近质心 16/24 = **66.7%**、列标准化 16/24 = 66.7%、kNN 15/24 = 62.5%。

**必须做等价口径比较**才看得出真相：5 类那次里，**非中性类**的成绩是 `5+3+6+3 = 17/25 = 68%`。

```
去掉「中性」类后：  68% → 66.7%      （n=24，噪声范围内）
整体区分度：      +0.0446 → +0.0463  （几乎未变）
```

→ **删掉那个"分不开的类"，并不会让其余类更容易分开。** 它只是把必然错的样本移出计分，
顺带把随机基线从 20% 抬到 25%，绝对准确率被动上升。**5.11.5 里"类目必须有抓手"这条建议，
实测没有带来可测量的收益。**

**定案结论**：以 `paraphrase-multilingual-MiniLM-L12-v2`（384 维）为编码器时，
**无法完成可用的多类主题分类**——四类最好 66.7%，其中两类接近不可分。
唯一稳定可分的是「情绪强度极高 + 词汇高度集中」的类（考试焦虑 +0.1005，7/7 全对，
评论普遍含"考试/挂科/补考"这类强特征词）。

**一句话**：这个模型能判"这句话有多激烈"，不能判"这句话在说什么事"。
要真正做主题分类，只能换更强的编码器（代价见右侧）：体积 448 MB → 约 1.2 GB、
单条推理约 50 ms → 200–400 ms、内存约 553 MB → 约 1.5 GB，且维度 384 → 1024 需改
`onnx_infer.cpp` 取向量那一处与 `comment_mean_dim` 配置。

**这个负结果是有价值的**：它用不到一天的成本排掉了一条会耗掉几周的路。

## 5.12 换回模型的原始场景重测：STS 区分度 +0.1833（纠正 5.11 的评测错配）

### 5.12.1 5.11 错在哪

5.11 用「主题分类」和「意图分类」评这个模型，**属于任务错配**：

`paraphrase-multilingual-MiniLM-L12-v2` 的训练目标是 **STS（语义文本相似度）**——
判断两句话**是不是同一个意思**。而本项目实际做的事（评论 vs 模板算余弦）恰好就在它的原始用途里。

**同主题 ≠ 同义。** 典型例子：

```
「已挂不欠」  vs  「洛必达好难」     同属考试话题，但不是同一个意思
模型给出 0.72 —— 在 STS 语义下这是【正确的】
而 5.11 把它判成"不可分"，等于把"模型正确地没把两句话认成同义"当成"模型分不清主题"
```

### 5.12.2 按原始场景重测

工具 `tools/sts_eval.cpp`，语料 `tools/sts_pairs.txt`（21 对真实评论，11 同义 / 10 非同义，
标签为人工初判、待复核）。同义对如
「好便宜，我也把我漫步者扔了」/「很便宜，我把我的索尼xm5扔了买这个」、
「补考刷到」/「10点补考，现在开看」。

| 指标 | 值 |
|---|---|
| 同义对平均余弦（11 对） | **0.8429**（0.6716 ~ 0.9794） |
| 非同义对平均余弦（10 对） | **0.6596**（0.5057 ~ 0.9026） |
| **区分度（同义 − 非同义）** | **+0.1833** |
| 最优阈值 0.7251 下准确率 | 18 / 21 = **85.7%** |

### 5.12.3 三种测法对比：同一个模型，差 4 倍

| 测法 | 结果 | 是否模型的职责 |
|---|---|---|
| 主题分类（5 类，5.11.2） | 63.3%（随机基线 20%） | ❌ 错配 |
| 意图分类（4 类，5.11.6） | 66.7%（随机基线 25%） | ❌ 错配 |
| **STS 同义判定（本节）** | **85.7%，区分度 +0.1833** | ✅ **本职** |
| 主题式区分度（5.11.2） | +0.0446 | ❌ 错配 |
| **STS 区分度（本节）** | **+0.1833** | ✅ **本职** |

**区分度差 4 倍、准确率差 20 个百分点，全部来自"问错了问题"。**

### 5.12.4 三条限定（引用时必须带上）

1. **样本量 21 对太小**，置信区间约 ±15 个百分点，只能当趋势，不能当指标。
2. **85.7% 是在同一批数据上穷举最优阈值得到的，属于上界**；实际部署不能用事后阈值。
   **该引用的是无阈值的 +0.1833。**
3. 标签为人工初判，且 4 条同义对是最小改动构造的（非纯真实评论），**待复核后方可称"人工标注"**。

### 5.12.5 对项目定位的影响

前几节里"真实区分度只有 +0.0649 / 意图分类 63.3%"这些结论，**是评测方式造成的偏低**，
不是模型在这个项目里的真实表现。项目做的事是 STS，正确口径是 **+0.1833**。

同时保留 5.11 的价值：它证明了**这个模型做不了主题分类**——这一点仍然成立，
只是不该被当作"模型效果差"的证据。

## 可迁移的经验

1. **结论的作用域不得大于证据的作用域**——一个端点失败推不出全部失败，
   一个进程挂着连接推不出它在偷流量，一个文件体积推不出模型家族。
2. **凡是「按位置编号」的数据（词表、embedding 行、数组索引、行号），"转换"前先问：
   它保留的是字节，还是语义？** 格式能互转 ≠ 编号等价。
3. **验证要用真实组件**。排查 5.6 时我先用贪婪匹配近似分词，得到 −0.1337 并据此说
   "语义系统性反转"；换成真实 `sentencepiece.lib` 后只有 −0.0149，定性应修正为"区分度失效"。
   近似品只能用来快速排除嫌疑。
4. **生成物必须可重生成，且不得比源码陈旧**。一份展示着已修复 bug 的 HTML 文档是负资产。
5. **"看起来正常"是一个待验证项**。本项目的两个最严重缺陷（5.3、5.6）都不报错。
